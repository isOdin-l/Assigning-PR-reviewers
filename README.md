[![Docker](https://img.shields.io/badge/Docker-2496ED?style=flat-square&logo=docker&logoColor=white)](https://www.docker.com/)
[![PostgreSQL](https://img.shields.io/badge/PostgreSQL-336791?style=flat-square&logo=postgresql&logoColor=white)](https://www.postgresql.org/)
[![OpenAPI](https://img.shields.io/badge/OpenAPI-6BA539?logo=openapiinitiative&logoColor=white)](https://www.openapis.org/)

Сервис для автоматического назначения ревьюверов кода для pull request внутри команд разработки. Сервис управляет командами, пользователями и pull request.

## Архитектура

### Структура
Монолитной архитектуре сервиса с четким разделением на слои:

1. **API Handlers** - RESTful HTTP endpoints со спецификацией OpenAPI 3.0
2. **Бизнес-логики** - Обработчики, реализующие основные бизнес-правила
3. **Доступа к данным** - Repository слой для операций с базой данных
4. **Базы данных** - PostgreSQL для постоянного хранения данных

### Основные компоненты
- **Управление командами** - Создание и управление командами
- **Управление пользователями** - Обработка профилей пользователей и статуса активности
- **Управление Pull Request** - Создание и отслеживание PR
- **Назначение ревьюверов** - Назначение 0-2 ревьюверов на каждый PR
- **Переназначение ревьюверов** - Замена ревьюверов на свободных участников команды

## Стек

### Бэкенд
- **Язык**: Go 1.25.4
- **Веб-фреймворк**: Chi 
- **База данных**: PostgreSQL 18.1
- **Библиотеки для работы с БД**: 'pgx/v5' и sql builder 'squirrel'
- **Спецификация API**: OpenAPI 3.0 с oapi-codegen
- **Конфигурация**: Переменные окружения, получаемые с помощью 'caarlos0/env'

### Инфраструктура
- **Контейнеризация**: Docker & Docker Compose
- **Миграции базы данных**: SQL скрипты в init/schema
- **Управление секретами**: Docker secrets
- **Проверки здоровья**: Встроенный мониторинг здоровья PostgreSQL


## Ключевые возможности

### Назначение ревьюверов
- Автоматически назначает 0-2 ревьюверов из команды автора
- Исключает автора PR из пула ревьюверов
- Назначает только активных пользователей

### Идемпотентные операции
- Безопасные повторные попытки для операций слияния
- Согласованная обработка ошибок
- Транзакционные операции с базой данных

### Комплексный API
- RESTful endpoints с корректными HTTP статус-кодами
- Детализированные ответы об ошибках с кодами ошибок
- Документация OpenAPI
- Типобезопасная валидация запросов/ответов

### Основные таблицы
- **users** - Профили пользователей с привязкой к команде и статусом активности
- **pull_requests** - данные PR 
- **pr_reviewers** - Связь многие-ко-многим между PR и ревьюверами

## API Endpoints

### Команды
- `POST /team/add` - Создать/обновить команду с участниками
- `GET /team/get` - Получить детали команды

### Пользователи
- `POST /users/setIsActive` - Обновить статус активности пользователя
- `GET /users/getReview` - Получить PR, где пользователь является ревьювером

### Pull Requests
- `POST /pullRequest/create` - Создать PR с автоматическим назначением ревьюверов
- `POST /pullRequest/merge` - Пометить PR как слитый (идемпотентно)
- `POST /pullRequest/reassign` - Заменить конкретного ревьювера


## Запуск

```bash
docker compose up --build
```

### Конфигурация окружения
- Конфигурация сервера: `configs/server.env`
- Конфигурация базы данных: `configs/postgres.env`
- Секреты: `init/secrets/`

### Приложение
- Приложение: `localhost:8080`
- Все endpoints имеют префикс `/api/v0`

### Коды ошибок
- `TEAM_EXISTS` - Конфликт при создании команды
- `PR_EXISTS` - Дублирующийся ID PR
- `PR_MERGED` - Операция над слитым PR
- `NOT_ASSIGNED` - Ревьювер не назначен на PR
- `NO_CANDIDATE` - Нет доступного кандидата для замены
- `NOT_FOUND` - Ресурс не найден
- `SERVER_ERROR` - Ошибка на стороне сервера
